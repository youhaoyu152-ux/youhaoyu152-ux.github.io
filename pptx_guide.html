01. 核心逻辑与工具选择 (Overview)

SKILL.md 原文 (English) 中文解读与实操注释 (Chinese Commentary)
A `.pptx` is a ZIP archive of XML files. Choose your approach by task: | Task | Approach | |---|---| | **Create** a new deck | Write a `pptxgenjs` script — see gotchas below | | **Edit** an existing deck, or build from a template | unzip → edit `ppt/slides/slideN.xml` → zip | | **Read** content | `markitdown deck.pptx`; visual grid: `python scripts/thumbnail.py deck.pptx` |

核心理念： PPTX 文件本质上就是一个装了 XML 文件的压缩包（ZIP）。

三种工作流：

  • 新建 必须写 JavaScript 脚本（使用 pptxgenjs 库）来生成。
  • 修改 解压 PPTX，直接改里面的底层 XML 代码，再压回去。
  • 读取 用 markitdown 把 PPT 转成纯文本供 AI 阅读。

02. 新建 PPT 的“天坑”避坑指南 (Creating with pptxgenjs)

SKILL.md 原文 (English) 中文解读与实操注释 (Chinese Commentary)
- **Set `pres.layout` before adding slides.** The default canvas is `LAYOUT_16x9` = **10" × 5.625"**, not 13.3" wide. Coordinates past the edge are written, not clamped — the shape just isn't on the slide.

先定尺寸，再画图。 默认的画布其实很窄（16:9的比例下只有 10 英寸宽）。如果你把元素画到了边缘外，代码不会报错，但在 PPT 里你就是看不见它。
- **Hex colors: never `#`, never 8 digits.** `color: "FF0000"`. Both `"#FF0000"` and alpha baked into the hex (`"00000020"`) **corrupt the file**.

颜色代码会搞坏文件。 永远不要在颜色值前面加 #（比如写成 #FF0000）。也不要写 8 位带透明度的十六进制。这两种写法都会直接损坏 PPT 文件。
- **pptxgenjs mutates option objects in place** (converts values to EMU on first use). Never share one `shadow`/options object across two `add*` calls — build a fresh object each time.

对象复用陷阱。 这个库会偷偷修改你传入的配置对象（把数值转成内部单位）。所以，每次添加新元素（比如加阴影）时，都必须重新创建一个新对象，不能把同一个配置对象用在两个地方。
- **Shadow `offset` must be ≥ 0** — a negative offset corrupts the file. To cast a shadow upward, use `angle: 270` with a positive offset. - **`letterSpacing` is silently ignored** — the real option is `charSpacing`.

属性名写错不报错，但会出 bug。

  • 阴影的偏移量（offset）绝对不能是负数，否则文件损坏。想往上打阴影，用角度 angle: 270。
  • 调整字间距必须用 charSpacing，如果你写 letterSpacing，系统会直接无视。
- **Keep charts native.** Use `addChart()` for everything PowerPoint can chart... For PowerPoint-native features the library doesn't expose (trendlines, error bars), compute the extra series yourself or post-process the generated OOXML — do not fall back to a rendered image.

图表必须是“真”图表。 尽量用原生代码生成图表。对于库不支持的高级功能（如趋势线、误差棒），自己去改底层代码生成。千万别直接贴一张图表的截图上去。

03. 编辑现有模板与文件 (Editing existing decks)

SKILL.md 原文 (English) 中文解读与实操注释 (Chinese Commentary)
- **Do all structural work — add, delete, reorder — before editing any slide's content.** `add_slide.py` copies a slide file verbatim, so duplicating after you edit clones the edited content...

先搭骨架，再填血肉。 必须先完成所有“增加页、删除页、移动页”的操作，然后再去改具体页面的文字。因为如果你改了文字再去复制这一页，复制出来的也会带上刚改过的文字。
- **If you use `python-pptx`**, three things it won't do: duplicate a slide... preserve formatting through `text_frame.text = "..."`... or read the SVG/EMF most template art uses.

不要用 python-pptx 做高级编辑。 这个老库有三个致命缺陷：不能复制页面；直接赋值文字会丢失所有格式；读不了模板里的矢量图（SVG/EMF）。
- **Template slots ≠ source items.** If the template shows 4 team members and you have 3, delete the 4th member's entire group (image + text boxes), not just its text — then check for orphaned visuals in QA.

清理占位符要彻底。 如果模板上有 4 个团队头像，但你只有 3 个人。要删掉整个第 4 个模块（包括图片和文本框），不能只删文字，否则会留下一个幽灵图片。

04. 设计与排版规范 (Design Ideas)

SKILL.md 原文 (English) 中文解读与实操注释 (Chinese Commentary)
- **NEVER use accent lines under titles** — these are a hallmark of AI-generated slides; use whitespace or background color instead. - **NEVER add decorative color bars or accent stripes**...

极其重要的审美警告： 绝对不要在标题下面画一条装饰性的横线，也不要在页面边缘加彩色的竖条。这是 AI 生成 PPT 的典型特征（看起来很土）。请用留白或背景色来区分区块。
- **Safe fonts** (render true-to-width in QA *and* ship with Office): **Arial, Calibri, Cambria, Times New Roman...** - **Never default to Aptos** — Office's post-2023 default has no metric-compatible substitute here...

字体安全区。 尽量只用 Arial, Calibri 等自带安全字体。千万别用 Aptos（Office 2023 之后的默认字体），因为它在预览环境里渲染不稳定，会导致排版错位。
- **Don't default to blue** — pick colors that reflect the specific topic. - **Don't default to cream/beige backgrounds**...

拒绝默认审美。 不要动不动就用蓝色系，要根据你的主题选配色（文件里提供了一套调色板参考）。背景不要默认用米色或奶油色，老老实实用白色或品牌色。

05. 质量检测 (QA - Required)

SKILL.md 原文 (English) 中文解读与实操注释 (Chinese Commentary)
- **Text overflow or text cut off at a box or slide boundary — check this first.** It is the most common defect and always user-visible.

头号检查项：文字溢出。 生成完 PPT 转成图片后，第一眼必须看文字有没有超出边框或被切掉。这是 AI 生成 PPT 最常见的毛病。
pptxgenjs emits chart XML PowerPoint refuses to open, and every other tool accepts: python-pptx opens those decks, LibreOffice renders them, the XSD passes them. Every failure names its fix.

必须跑验证脚本。 pptxgenjs 生成的图表有时会有底层语法错误，导致别的软件能打开，但 PowerPoint 自己打不开。所以必须运行 validate.py 脚本进行全面体检。
